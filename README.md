## Как запустить

1. Распакуй `lab1_variant20.zip`. Открой папку `lab1_variant20`.
2. Открой терминал в этой папке. В Windows можно открыть папку в Проводнике, ввести `cmd` в адресной строке и нажать Enter. В VS Code: открой эту папку, затем меню «Терминал → Создать терминал».
3. Проверь наличие Python и установи единственную зависимость.

Windows:

```bat
py --version
py -m pip install -r requirements.txt
py run_all.py
```

Linux или macOS:

```bash
python3 --version
python3 -m pip install -r requirements.txt
python3 run_all.py
```

Если команда `py` отсутствует, но работает `python`, замени `py` на `python`. Если ни одна команда не работает, сначала установи Python 3 и снова открой терминал; при установке в Windows включи добавление Python в PATH. В Linux при запрете установки пакетов в системное окружение используй виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_all.py
```

В среде с уже установленным NumPy достаточно запуска `run_all.py`. Установка зависимости требует интернета; сами расчёты работают без интернета.

### Как изменить точность

В `tests/lr1_3.txt`, `tests/lr1_4.txt` и `tests/lr1_5.txt` первая строка содержит размер матрицы и точность. Например, `3 0.01` означает матрицу 3×3 и ε = 0.01. Чтобы получить более точный результат, замени `0.01` на `0.000001` и повтори запуск. Числа вводи через точку, не через запятую.

Точность в условиях не фиксирована. В основных файлах выбрана ε = 0.01, как в примере; дополнительно выполнены расчёты при 0.0001 и 0.000001. В заданиях 1.1 и 1.2 ε не задаётся: это прямые методы, ошибка обусловлена округлением чисел.

## Нужно ли просто заменить входные данные в примере

Алгоритмы должны быть универсальными: вариант меняет матрицы и правые части, а не математический метод. Поэтому каркас можно использовать повторно. Но в данном примере пришлось исправить вычисления и критерии остановки.

В задании 1.3 пример останавливается также по простому условию «разность приближений меньше ε», хотя это не гарантирует требуемую ошибку решения. Для Зейделя в примере неправильно составлен коэффициент оценки погрешности. В исправленном коде используются оценки из методички и нет дополнительной остановки, которая обходила бы эту оценку.

В QR-примере функция знака сравнивает отрицательную ветку с `eps` вместо `-eps`, нет обработки нулевого вектора отражения, а проверка элементов ниже первой поддиагонали недостаточна для получения всех вещественных корней. Исправленная программа проверяет изоляцию блоков 1×1 и 2×2 и стабилизацию комплексных корней.

Для LU явно выводятся P, L, U и проверяется равенство **PA = LU**. Правая часть не изменяется внутри решателя; вырожденная матрица выдаёт понятную ошибку. Для прогонки проверяется ненулевой знаменатель.

Большинство данных одногруппника соответствует варианту 16. При этом в его тесте 1.3 коэффициент при x₄ в первой строке равен −6, а в условии варианта 16 — −4. Поэтому его входные данные нельзя принимать за точную копию условий без проверки.

## Задание 1.1 — LU-разложение

### Условие варианта 20

```text
 7x₁ + 8x₂ + 4x₃ − 6x₄ = −126
 −x₁ + 6x₂ − 2x₃ − 6x₄ = −42
 2x₁ + 9x₂ + 6x₃ − 4x₄ = −115
 5x₁ + 9x₂ +  x₃ +  x₄ = −67
```

Нужно решить систему, найти определитель и обратную матрицу с помощью собственного LU-разложения с выбором главного элемента.

### Что делает программа

`lu_decompose` последовательно обнуляет элементы ниже диагонали. Множители исключения записываются в L, преобразованная матрица становится U. На каждом шаге выбирается максимальный по модулю элемент текущего столбца среди оставшихся строк. Перестановки записываются в P, поэтому верное равенство — PA = LU.

`lu_solve` решает две треугольные системы: Ly = Pb, затем Ux = y. `inverse_from_lu` решает системы с каждым столбцом единичной матрицы; найденные решения становятся столбцами обратной матрицы. Определитель — произведение диагонали U, умноженное на (−1) в степени числа перестановок.

Результат: **x = (−4, −5, −7, 5), det A = 2866**. Обратная матрица и разложение приведены в `results/lr1_1.txt`. Для этой матрицы перестановки не потребовались, P = I; сам выбор главного элемента реализован и проверен на других матрицах.

На защите покажи проверки PA − LU, Ax − b и AA⁻¹ − I. Их нормы около 10⁻¹⁴–10⁻¹⁶. Короткое объяснение: «Один раз раскладываю матрицу, затем решаю две треугольные системы для каждой правой части». Разложение требует O(n³) операций, решение с готовыми L и U — O(n²).

## Задание 1.2 — метод прогонки

### Условие варианта 20

```text
−6x₁ +  6x₂                       = 30
 2x₁ + 10x₂ −  7x₃                = −31
       −8x₂ + 18x₃ +  9x₄         = 108
               6x₃ − 17x₄ − 6x₅  = −114
                      9x₄ + 14x₅  = 124
```

Ввод — четыре строки длины 5, без отдельной строки размера:

```text
a:   0   2  −8   6   9
b:  −6  10  18 −17  14
c:   6  −7   9  −6   0
d:  30 −31 108 −114 124
```

В файле данных букв `a:`, `b:`, `c:`, `d:` нет. `a` — нижняя диагональ, `b` — главная, `c` — верхняя, `d` — правая часть. Здесь `b` обозначает диагональ, а не правую часть из задания 1.1. Нули a₁ и c₅ задают границы системы.

### Что делает программа

Прямой ход выражает каждую неизвестную через следующую: xᵢ = pᵢxᵢ₊₁ + qᵢ. Коэффициенты предыдущей строки подставляются в следующую. В последней строке следующей неизвестной уже нет, поэтому x₅ = q₅; обратный ход восстанавливает остальные x.

Результат: **x = (−5, 0, 3, 6, 5)**. Подстановка даёт вектор (30, −31, 108, −114, 124). На этих данных вычисленная невязка равна нулю в используемой арифметике.

На защите объясни, почему достаточно трёх диагоналей и двух проходов. Сложность O(n), а не O(n³). Делить можно только на ненулевые знаменатели прогонки. В этом варианте первая строка имеет равенство модулей диагонального и внедиагонального коэффициентов, поэтому нельзя утверждать строгое диагональное преобладание во всех строках; вычисленные знаменатели ненулевые.

## Задание 1.3 — простые итерации и Зейдель

### Условие варианта 20

```text
10x₁ −  x₂ −  2x₃ +  5x₄ = −99
 4x₁ + 28x₂ +  7x₃ +  9x₄ = 0
 6x₁ +  5x₂ − 23x₃ +  4x₄ = 67
  x₁ +  4x₂ +  5x₃ − 15x₄ = 58
```

Нужно реализовать оба метода и сравнить число итераций при заданной точности.

### Что делает программа

`equivalent_system` делит каждое уравнение на диагональный коэффициент и получает x = αx + β. Диагональ α равна нулю, βᵢ = bᵢ/aᵢᵢ. Начальное приближение — β. Оно не считается отдельной итерацией.

В методе простых итераций, здесь в форме Якоби, все компоненты нового вектора вычисляются из старого вектора. В методе Зейделя уже найденные компоненты текущего прохода сразу используются при расчёте следующих.

Норма матрицы здесь — максимальная сумма модулей элементов строки. Норма вектора — максимальный модуль компоненты. Для варианта 20 q = ‖α‖∞ = 0.8 < 1: сходимость обеспечена. Условие остановки Якоби: q/(1−q) · ‖x⁽ᵏ⁾−x⁽ᵏ⁻¹⁾‖∞ ≤ ε. Для Зейделя в числителе используется ‖C‖∞, где C — строго верхняя часть α; знаменатель остаётся 1−‖α‖∞. Здесь ‖C‖∞ = 0.8, поэтому коэффициент оценки в обоих методах равен 4.

Точное решение для проверки: **x* = (−8, 4, −5, −5)**.

| ε | Итераций Якоби | Итераций Зейделя | Фактическая ошибка Якоби | Фактическая ошибка Зейделя |
|---|---:|---:|---:|---:|
| 0.01 | 10 | 5 | 1.3881·10⁻³ | 7.1751·10⁻⁵ |
| 0.0001 | 16 | 7 | 7.5679·10⁻⁶ | 2.5245·10⁻⁷ |
| 0.000001 | 22 | 9 | 1.0165·10⁻⁷ | 2.1250·10⁻⁹ |

Фактические ошибки определены сравнением с независимым эталоном в проверках. Рабочий алгоритм использует оценку, поскольку точное решение в общем случае заранее неизвестно.

На защите объясни разницу в использовании старых и новых компонент. Для этой системы Зейдель требует меньше итераций; это результат эксперимента, а не правило для любой матрицы. Условие q < 1 — достаточное, но не необходимое. Не путай ошибку решения ‖x−x*‖ с невязкой ‖Ax−b‖: они не равны. Поэтому невязка больше ε сама по себе не опровергает полученную оценку ошибки решения.

## Задание 1.4 — вращения Якоби

### Условие варианта 20

```text
A = [−7  −9   1]
    [−9   7   2]
    [ 1   2   9]
```

Нужно найти собственные значения, собственные векторы и исследовать связь точности с числом вращений.

### Что делает программа

На каждом шаге `jacobi_rotations` выбирает наибольший по модулю внедиагональный элемент. Строится ортогональное вращение U, которое обнуляет этот элемент в UᵀAU. Произведение всех вращений накапливается в V. Когда матрица становится почти диагональной, её диагональ даёт собственные значения, а столбцы V — соответствующие собственные векторы.

Остановка: t = √(Σᵢ<ⱼ aᵢⱼ²) ≤ ε. Это норма верхнего внедиагонального треугольника, а не непосредственно ошибка каждого собственного значения. Полная внедиагональная норма Фробениуса равна √2·t.

При ε = 0.01 значения отсортированы по возрастанию:

```text
λ₁ ≈ −11.5559755260
λ₂ ≈   8.5193853876
λ₃ ≈  12.0365901384

v₁ ≈ (−0.8926937457, −0.4422922944,  0.0864604114)
v₂ ≈ ( 0.2588512243, −0.3461710340,  0.9017547665)
v₃ ≈ ( 0.3689090946, −0.8273712236, −0.4235126189)
```

| ε | Вращений | Итоговая t | Максимальная невязка ‖Av−λv‖∞ | Ошибка собственных значений по эталону |
|---|---:|---:|---:|---:|
| 0.01 | 5 | 2.2272·10⁻⁴ | 2.0094·10⁻⁴ | 1.4104·10⁻⁸ |
| 0.0001 | 6 | 5.5082·10⁻⁷ | 4.9171·10⁻⁷ | около 1.2·10⁻¹⁴ |
| 0.000001 | 6 | 5.5082·10⁻⁷ | 4.9171·10⁻⁷ | около 1.2·10⁻¹⁴ |

История t после 0–5 вращений: 9.273618495 → 2.236067977 → 1.357279074 → 0.116901128 → 0.049648929 → 0.000222724. При шестом вращении t сразу становится меньше и 10⁻⁴, и 10⁻⁶, поэтому число вращений для двух точностей совпадает.

На защите покажи Av ≈ λv и VᵀV ≈ I. Метод применяется к вещественной симметричной матрице. Векторы нормированы; изменение знака собственного вектора допустимо. Порядок вывода λ и соответствующих векторов может отличаться от другого решения.

## Задание 1.5 — QR-разложение и QR-алгоритм

### Условие варианта 20

```text
A = [ 6   5  −6]
    [ 4  −6   9]
    [−6   6   1]
```

Нужно самостоятельно реализовать QR-разложение и на его основе найти все собственные значения. Собственные векторы в этом задании не запрашиваются.

### Что делает программа

`qr_decompose` использует отражения Хаусхолдера H = I − 2vvᵀ/(vᵀv). Они последовательно обнуляют элементы столбцов ниже диагонали. Получаются ортогональная Q и верхняя треугольная R, такие что A = QR. В коде v предварительно нормируется, поэтому знаменатель уже равен единице.

`qr_algorithm` повторяет Aₖ = QₖRₖ, Aₖ₊₁ = RₖQₖ. Поскольку Aₖ₊₁ = QₖᵀAₖQₖ, преобразование сохраняет собственные значения. Используется алгоритм без сдвигов из методички. Он сходится на варианте 20 и на приложенных проверочных примерах.

Для вещественного корня проверяется малая норма элементов под соответствующей диагональю. Для комплексной пары выделяется изолированный блок 2×2, решается его квадратное характеристическое уравнение и проверяется стабилизация корней между соседними итерациями. В варианте 20 все три корня вещественные.

Результат при **ε = 0.01**, после 30 QR-итераций:

```text
λ ≈ (−13.2754808999, 9.8607305110, 4.4147503888)
```

Более точный эталон для сравнения:

```text
λ* ≈ (−13.2762930110, 9.8615426222, 4.4147503889)
```

| ε | QR-итераций | Максимальная ошибка спектра по эталону |
|---|---:|---:|
| 0.01 | 30 | 8.1211·10⁻⁴ |
| 0.0001 | 45 | 9.3561·10⁻⁶ |
| 0.000001 | 61 | 8.0353·10⁻⁸ |

На защите покажи A ≈ QR и QᵀQ ≈ I и объясни, почему смена порядка множителей сохраняет спектр. `+0j` в выводе означает нулевую мнимую часть, то есть вещественное число. Для произвольной несимметричной матрицы комплексные значения допустимы.

ε здесь задаёт критерий малости поддиагональных элементов и стабилизации комплексной пары, а не универсальную строгую границу ошибки каждого собственного значения несимметричной матрицы. Для этого варианта фактическая ошибка проверена отдельно. QR без сдвигов может сходиться медленно или не сходиться на отдельных спектрах; предусмотрен предел итераций с сообщением об ошибке. Результат для варианта 20 получен именно этим алгоритмом, без библиотечного вычисления собственных значений.
